两轮模型请求均以四条评价为一批并行发送，没有批次失败。编号越界、重复类别、过长或命中隐私模式的片段先丢弃。发布时按证据线索再筛掉 4,849 条提案，将 2 条明确的部分缺件从整单未到改为缺件。未完成翻译的那条评价回落到规则。重算默认给全部步骤 2,280 秒，优先保留复核和翻译所需时间。

## 逐条与四条合批

在同一台机器上用 48 条固定评价对照，只测编号选择，两个版本都关闭提示缓存并使用 16 并发上限。

| 请求方式 | 请求数 | 输入 token | 输出 token | 用时 |
| --- | ---: | ---: | ---: | ---: |
| 每批一条 | 48 | 30,405 | 350 | 9.753 秒 |
| 每批四条 | 12 | 8,733 | 416 | 5.660 秒 |

四条合批减少约 **71.3%** 的输入 token，因为同批评价共享提示。实测两种方式的 API 费用均为零。合批会改变生成上下文，因此单独约束批内行数和引用编号，并以全量输出的评估指标衡量准确率。
